# M4：额度采集与动态预算

## 配置和启用

先运行 `flask db upgrade`（迁移 `0003`）。原配置保持原来的固定限额；新增规则按下面的影子模式观察两周，再修改 `mode: enforce` 并热重载。两个小时规则同时执行时取约束最紧的一条，若希望完全切换到动态预算，应删除固定的 `hourly_cap`。

```yaml
upstreams:
  - name: router-team-a
    base_url: http://router-team-a:20128
    api_key: "${ROUTER_TEAM_A_KEY}"
    quota:
      password: "${ROUTER_TEAM_A_PASSWORD}"
      refresh: 3m
      stale_after: 6m

pools:
  - name: team-a/claude
    kind: claude
    upstream: router-team-a
    keys: ["${LQ_TEAM_A_CLAUDE}"]
    connections: ["<9router connection id>"]
    rules:
      - {kind: hourly_cap, limit: 20}
      - kind: hourly_budget
        cycle_limit: 800
        cycle_period: 7d
        anchor: upstream_reset
        weight_profile: workday
        timezone: Asia/Shanghai
        flex: 0.5
        h_min: 2
        h_max: 30
        short_limit: 100       # 示例，必须按本订阅实测
        mode: shadow
      - {kind: cycle_cap, cycle_limit: 800, cycle_period: 7d,
         anchor: upstream_reset, on_exceed: reject, mode: shadow}
```

`quota` 不依赖 Dashboard 入口是否开放，也不依赖价格源。价格与额度使用相同地址和密码时共享登录会话；登录失败（含网络失败）后等待至少 30 分钟再登录。改变密码后重建会话。

默认自动选择该池 `kind` 唯一的活跃 OAuth 连接；存在多个时必须配置 `connections`，否则报告采集失败。显式指定多个连接时逐个读取，同名窗口保守地用最高使用率约束，不能把它们的比例简单相加或平均。推荐每个账户单独建池，才能准确对齐独立的周期。

## 小时权重与预算

`R = max(0, cycle_limit − used_cycle)`；`base = R × 当前权重 / 剩余小时权重和`；`H = clamp(base × (1 + flex), h_min, h_max)`，最后由短窗口余量及紧急刹车收紧。剩余权重包含完整的当前小时，周期尾部不足一小时的部分按比例计入。默认时区显式固定为 `Asia/Shanghai`，可按规则配置 IANA 时区，不受宿主机时区影响。

内置 `flat` 是 168 个 1；`workday` 是工作日 09–19 点为 1，其余时段 0.2，周末 0.5。可覆盖或新增配置，支持正数的 168 项列表（周一 00 点开始）或下面的简写；简写中未覆盖的小时默认 0.2，重叠区间、零权重和非有限数值均拒绝：

```yaml
weight_profiles:
  workday:
    weekday: {"09-12": 1, "13-19": 1, "19-24": 0.6, "00-09": 0.2, "12-13": 0.5}
    weekend: {"10-22": 0.5, default: 0.2}
```

周期长度为 1h–31d；`anchor` 支持 `upstream_reset`、Unix 时间、`"mon 00:00"` 等星期加时间。上游重置时间未知时，`upstream_reset` 回退到该时区周一零点。历史重置时间即使已经过期仍可用来推算周期边界，但过期窗口的使用率不再约束新周期。

预算每个整点、周期切换、上游比例累计变化至少 1 个百分点、跨越 90%/98%、数据过期、配置重载和管理员覆盖时重算，写入 `budget_snapshots`。后台即使没有请求也会计算。`used_cycle` 和 `S_rem` 实时更新，扣除上次成功采集之后本地已经计入的费用，避免两次采集之间重复花掉同一份余量。

`short_limit` 表示短窗口（5h）总额度的 eUSD 估计值。有有效的短窗口百分比时使用其真实余量，同时受本地最近 5h 消耗约束；采集缺失或过期时回退到本地 5h 计数。未配置时 `s_rem: null`，不会根据百分比猜测美元额度。短窗口余量耗尽直接拒绝，不能由排队超时放行。

规则支持 `scope: {model: "claude-opus-*"}`，默认 Opus 作用域读取 `weekly_opus`，其他作用域读取 `weekly`；可显式设置 `quota_window: weekly_sonnet`。计数保留实际模型名，所以热重载新增作用域也能统计之前的周期费用。`session_aware: true` 可用于 FIFO 动态预算，行为与固定小时限额相同。

## 采集、失效与紧急刹车

后台每 3 分钟请求 `/api/providers` 和各连接 `/api/usage/{id}`，适配 9router 的 `quotas` 对象，包括 Claude 的 `session (5h)` / `weekly (7d)` / `weekly opus (7d)` 与 Codex 的 `session` / `weekly`。不支持的独立功能窗口（如 Codex review）不混入普通对话预算。接口字段依据 [9router Claude 实现](https://github.com/decolua/9router/blob/master/open-sse/services/usage/claude.js) 和 [Codex 实现](https://github.com/decolua/9router/blob/master/open-sse/services/usage/codex.js) 核对。

只绑定一个连接时，也读取响应头补充观测：Codex 使用 `x-codex-{primary,secondary}-used-percent`，Claude 使用 `anthropic-ratelimit-unified-{5h,7d}-utilization`（0–1）。多连接请求的响应头缺少账户标识，因此不参与校准。请求体、SSE 字节和上游状态码维持透传。

HTTP 失败、空 `quotas`、返回错误消息或无效字段都算采集失败，保留上次数据并立刻标记过期、告警。过期比例不再用于预算和周期费用校准；高使用率的刹车则保守保留到该窗口的已知重置时间，或直到新数据证明恢复。没有重置时间且持续采集失败时，不会自行假定额度恢复。

- 任意受支持窗口 ≥90%：执行中的动态预算不高于 `h_min`（`S_rem` 仍能进一步收紧）。
- 任意受支持窗口 ≥98%：有执行中的动态预算／周期规则时立即拒绝，包括已经在排队的请求。
- `cycle_cap` 到达周期费用上限立即拒绝；支持独立模型作用域。
- 紧急拒绝和周期硬上限优先于管理员 `lift` / `limit`、FIFO／phase 和队首超时；90% 的最低预算也不能被临时放宽。已经转发的流继续完成，已计费用保留。
- `mode: shadow`／`on_exceed: shadow` 只展示、记事件和 `shadow_would_hold`，不执行该规则的拒绝与收紧。若需全部影子观察，应同时将 `hourly_budget` 和 `cycle_cap` 设为 shadow。

周期硬上限和小时限额均基于已计费用；沿用项目不预估请求成本的约定。单个大请求及已在途请求可能使最终费用超过上限，但达到上限后的新请求会被拒绝。

## 观测、持久化与验证

`/status` 和状态首页展示每条预算的 `h_value`、`remaining_r`、权重、周期、短窗口余量、模式，以及额度窗口、过期状态、采集错误、刹车档位。`quota.calibration` 给出两次同周期观测之间的 `ΔeUSD / Δ百分点` 和 `suggested_limit`，只提示，不自动修改配置。存在绕过灵渠的流量或多账户时，该估算需人工复核。

`POST /admin/quota/sync`（管理员鉴权）立即采集，任一池失败返回 502 及按池列出的错误。刹车进入、升级和恢复分别记录 `quota_minimum` / `quota_reject` / `quota_recovered` 事件并告警。

`upstream_quota` 保存成功的额度观测；`budget_snapshots` 保存预算计算及输入；`cycle_spend_snapshots` 保存最近 32 天按实际模型和精确计入时刻累计的费用。账本新增 `accounted_at` 保存最终费用的精确计入时间，避免用截断到毫秒的请求耗时推算检查点归属。重启加载快照，再分别补记账本中尚未计入的输入和输出，避免进行中的请求在检查点两侧被重算。恢复的上游观测先标记过期，待采集确认；高水位刹车继续保留。管理员重置滚动计数不会清除长周期费用，也不能解除周期硬上限。

当前回放仍按固定小时限额比较策略，不会重建历史的上游额度变化；M4 的上线对照应使用实时影子预算和预算快照。不会自动学习最近四周的权重；需要部署方生成 168 项权重后热重载。额度与预算观测表目前不自动清理，长期运行需按部署方的留存策略归档。

验证命令：`python -m unittest discover -s tests`。新增测试覆盖预算公式、时区与权重、范围校验、采集协议和登录冷却、数据失效、阈值跨越、覆盖优先级、影子模式、排队唤醒、代理透传、长周期检查点恢复与迁移升级／回退。
