# 灵渠界面规范

## 目标与现状

灵渠的总览、控制台、Dashboard 入口和用量分析页应有明确的共同产品身份。它们可以采用不同的信息密度，但导航、字号、配色、操作反馈和页面宽度必须一致。

本次检查基于仓库模板和线上未登录入口。线上 `/usage/` 会跳转到 `/console/login?next=/usage/`，原用量页不属于 Lingqu 仓库。后续经用户授权通过 SSH 找到并取回源码，原位置是独立 deploy 仓库的 `k8s/jiuquyi/usage/`，已确认其确实有另一套独立样式；源码现已迁入 Lingqu 的可选 usage 模块，共用统一模板和样式；已于 2026-11-08 上线。

| 维度 | 原有问题 | 统一规则 |
| --- | --- | --- |
| 页面框架 | 总览与入口各自写 HTML，控制台另有 Bootstrap 基础模板 | `base.html` 负责文档、品牌、主导航、正文和页脚 |
| 配色 | 控制台固定黑色导航，其他页随系统改变深浅色 | 中性背景、表面、边框与蓝色强调色，全部随系统适配 |
| 滚动条 | 长页出现滚动条、短页不出现，导致 15px 宽度差或 7.5px 横移 | 根元素统一 `scrollbar-gutter: stable`；旧浏览器回退为固定竖向滚动条 |
| 内容宽度 | 总览 90rem、入口 72rem、控制台全宽 | 外框最大 1440px，两侧 32px，手机 16px |
| 字号与间距 | 各页有独立字号、页边距和控件尺寸 | 正文 14px，主标题 26px，区块标题 16px，正文间距以 8px 为基础 |
| 导航 | 一页是下划线链接，一页融入黑色导航 | 顶部主导航表示页面位置，页内标签表示分区和时间范围 |
| 信息层级 | 状态、版本、刷新、费用等挤在一行 | 页面标题和说明 → 关键指标 → 流量池 / 数据表 → 辅助信息 |
| 组件 | 卡片、表格、输入、按钮独立实现 | 共用 `lingqu.css`；Bootstrap 提供布局和基础交互样式 |
| 空状态 | 表格空行样式各异，计量空行跨列数不完整 | 使用居中空状态，完整跨越表格列 |
| 窄屏 | 全局内容和数据表的横向滚动缺乏区分 | 页面无横向溢出，宽表在独立容器内滚动，指标降为两列 |

## 视觉与交互

视觉方向是克制、清晰的运维产品界面。保留原有蓝色品牌联系，增加共用的渠道标记，使用留白和细边框划分内容。无需装饰插图，数据与操作优先。

所有颜色从 `app/static/lingqu.css` 的 `--lq-*` 变量派生，组件不再各自维护颜色表。浅色背景 `#f5f7fa`、表面 `#ffffff`、正文 `#202c40`、强调色 `#2563eb`；深色模式在同一文件集中覆盖。系统字体优先，中文回退至苹方、微软雅黑，不依赖外部字体或 CDN。

- 蓝色表示主要操作和当前位置；正常、警告、异常使用语义颜色并同时保留文字。
- 卡片圆角 12px，按钮和输入圆角 7px；卡片以边框为主，避免厚重阴影。
- 普通按钮统一尺寸，退出等次要操作使用中性描边，重要提交使用主色。
- 数值使用等宽数字；池名和机器标识使用等宽字体。
- 主导航与页内导航用 `aria-current="page"` 标注选中项，表单有可见标签，错误通过 `role="alert"` 呈现。
- 保留明显键盘焦点、跳到正文链接和系统减少动画偏好。
- 总览继续每 15 秒刷新；控制台表单保持现有认证、CSRF、提交与重定向行为。

## 模板与组件

- `base.html`：共用文档与页面外框。子页覆写 `title`、`head`、`header_actions`、`main_class`、`content`、`footer`、`styles`、`scripts`。
- `_nav.html`：只输出导航结构，样式由共享 CSS 维护。保留 `server.links` 配置方式，未配置链接且未启用 usage 时不额外显示主导航。
- `console_base.html`：保留控制台子模板继承入口，将 `logout` 放入统一页头。
- `lq-page-head`：页面标题、用途说明与状态。
- `lq-metrics` / `lq-metric`：桌面四列、手机两列的关键指标。
- `lq-section-head`：区块标题、辅助说明和筛选。
- `lq-tabs` / `lq-periods`：分区和时间范围。
- `lq-pool-grid` / `lq-pool`：随宽度自动排列的流量池卡片。
- `wrap` / `table-responsive`：可横向滚动的表格表面。
- `lq-auth-main` / `lq-auth-card`：统一登录卡片。

## 用量页接入

原独立用量服务已迁入 `app/usage/` 和 `app/status/usage.py`。页面继承 `base.html`，图表 / 额度局部样式限定在 `.lq-usage` 内，颜色从共享设计变量派生，不影响总览的同名组件。前端脚本从单文件 HTML 拆出，动态配置通过 Jinja `tojson` 安全传递，仅包含文案和本地路由。

保留时间 / 上游 / 分组筛选、指标切换、明细维度、排序与图表交互，并明确区分 New API 计费金额和限流用 eUSD。登录过期、同步失败、记录不完整和缺失额度均提供可见提示。启用配置、数据边界及上线迁移步骤见 [USAGE.md](USAGE.md)。

原始源码于 2026-11-08 从服务器 deploy 仓库恢复，已核对与 GitHub `c5a2543` 及线上 ConfigMap 一致。本次合并代码保持该部署仓库中的原始副本不变，后续以 Lingqu 内置模块为维护入口；线上已完成切换，见[发布记录](releases/2026-11-08-ui-usage.md)。

## 验证方式

现有页面、登录回跳、CSRF 与 Dashboard 行为使用项目自带 unittest 验证。视觉检查使用独立测试配置和真实 Chromium 渲染 Flask 响应，不访问生产数据：桌面 1440px、手机 390px，以及最窄 320px；覆盖深浅色、总览、登录、控制台全部八个分区和 Dashboard 入口。截图是测试数据预览，不代表线上已部署。


本次合并后的验证结果：完整 unittest 套件 219 项通过，包含新增 17 项 usage 测试；新旧服务的统计在 45 种时间 / 上游 / 分组组合下匹配。Chromium 的桌面 1440px、手机 390px（均含深浅色）和窄屏 320px 检查通过，覆盖登录回跳、图表、筛选、明细切换、键盘排序与页面横向溢出。生产环境已部署并完成公开 HTTPS 浏览器验收。

取回源码验证：Python 语法检查通过；仅在本地启动 HTTP 层，页面、healthz、stats、quotas 四个接口均返回 200。未启动后台采集 / 限流线程，未连接生产数据，也未修改或重启线上服务。
